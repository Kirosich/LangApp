# LangApp — контекст для Claude Code

## Кто пользователь и зачем это приложение
Личное приложение для изучения казахского (A2→B1, активное освоение) и
английского (B2, поддержание уровня). Испанский — фоновый, третий язык
(~30 слов), не приоритет. Работает в маркетинговом агентстве, ведёт побочный
проект эфиргейм.рф (платформа для стримеров/спонсоров, на нём же и живёт этот
langapp) и помогает с TikTok-стримами — эти проекты используются как материал
для примеров на английских занятиях.

### Казахский — self-study, ~2.5 часа/день
20-часовой план из 8 блоков (см. курс "Казахский — грамматика" в разделе
Теория → «Мой план»). Методология: сначала пробует конструкции сам, потом
просит проверить (active recall); предпочитает понимать логику грамматики
(корни, аффиксы, падежи, маркеры времени), а не зубрить; работает по
чек-листам. Ресурсы: kaz-tili.kz (Валяева, оглавление на in-soderj.htm)
для грамматики, Pimsleur для аудио. Принципы: агглютинативный язык
прогрессирует нелинейно, плато — норма; лучше 2 короткие сессии в день, чем
одна длинная; сон влияет на закрепление. Цели: автоматизм простых
конструкций (~40-50ч суммарно), функциональная речь (~150+ч).

### Английский — структурированный курс грамматики, B2 (самооценка)
20 часов, 5 модулей (см. курс "English Grammar — Elijah" в разделе Теория →
«Мой план»): Perfect Tenses (приоритет, 6ч) → Conditionals (4ч) → Articles
(4ч) → Prepositions (3ч) → свободная практика (3ч). Слабые места по
диагностике: Past Perfect (стабильно пропускается), артикли/предлоги
(напр. "in the marketing agency" вместо "at a marketing agency", "a free
time" вместо "free time"), согласование has/have в 3-м лице, согласование
this/these, порядок слов с "already". Подход: объяснять логику, а не
только правило; примеры — из реальных проектов пользователя; при
неуверенности замедляться, не спешить дальше; пользователю нравится, когда
дают выбор, что делать дальше. Дублирующий трекер вне приложения:
/mnt/user-data/outputs/english-grammar-plan-20h.md.

**Статус на 2026-08-21**: для каждого из этих слабых мест теперь есть
отдельная тема в справочнике теории (`en-past-perfect`, `en-articles-basics`,
`en-articles-common-mistakes`, `en-prepositions-place-time`,
`en-prepositions-work`, `en-dependent-prepositions`,
`en-subject-verb-agreement`, `en-adverb-word-order` — категории Tenses/
Articles/Prepositions/Agreement & word order), с дриллами на каждую. Но это
темы только что добавлены и ещё не пройдены пользователем (проверено по
`theory_progress` — `read_at` пусто), так что список слабых мест выше пока
нельзя считать закрытым — это гипотеза, которую подтвердит только реальная
практика. Не удаляй этот список, пока не увидишь через
`GET /api/coaching/summary` или прогресс по этим темам, что проблема
реально ушла.

## Стратегия обучения (важно соблюдать при генерации любого контента)
- Слова и фразы группируются ПО ТЕМАМ (еда, природа, числа/время, бытовое,
  глаголы), а НЕ парами "казахское слово = английское слово". Прямое
  парное сопоставление двух языков создаёт интерференцию и не используется.
- Английский используется только как точечная мнемоническая опора — если
  есть реальное фонетическое или лексическое сходство с казахским словом.
  Не создавай карточки специально "для сравнения" языков.
- Казахского контента (диалогов, фраз, примеров) в открытом доступе мало —
  при добавлении карточек старайся сразу давать транскрипцию (когда звук
  неочевидный) и пример использования в предложении, не только голый
  перевод.
- **Весь генерируемый контент (карточки, тексты для чтения, грамматика,
  диалоги) — оригинальный, никогда не копируется из внешних источников.**
  Это не просто стилистическое предпочтение — при обсуждении раздела
  чтения (2026-08-21) пользователь согласился заменить свой изначальный
  запрос "50% из открытых источников" именно из-за юридического риска
  копирования чужих текстов в самохостед-приложение. Если попросят
  добавить контент "из реальных источников" — предложи вместо этого
  оригинальный текст в соответствующем стиле/жанре, не скрапинг.
- При запросе "сделай упражнения/слова на тему X" — сначала проверь, есть
  ли уже карточки с этой темой в БД (дедуп по `language`+`term`), не
  дублируй, добавляй только новое.

## SRS: FSRS (не SM-2)
Планирование карточек — по FSRS (`server/srs/fsrs.js`, обёртка над
`ts-fsrs`), не по SM-2. Целевая вероятность вспоминания (`request_retention`)
хранится в `fsrs_settings`, сейчас 0.9. Каждое повторение пишется в
`review_log` (card_id, rating, elapsed_days, scheduled_days) — это сырьё для
будущей персонализации весов алгоритма под конкретного пользователя, но
**веса пока дефолтные** (в `review_log` пока 0 записей на момент последней
проверки — персонализация не запускалась, рано).

Старые SM-2-поля в `progress` (`easiness_factor`, `interval_days`,
`repetitions`, `due_date`, `last_reviewed`) оставлены в схеме для
сравнения/отката, но больше не обновляются — застыли на значениях до
миграции. Если видишь их в коде — это заморозка, не баг.

## Форматы упражнений
Карточки (SRS):
- Основной цикл — Study с оценкой Again/Hard/Good/Easy (FSRS)
- «Тренировка» — свободный прогон без оценок и без влияния на расписание
  (бонус-раунд или отдельный вход с дашборда на N слов)

Квизы (`server/routes/quiz.js`, `VALID_TYPES`):
- **choice** — multiple choice
- **typing** — с толерантностью к опечаткам (Левенштейн ≤1) и поддержкой
  нескольких приемлемых ответов через `/` или `,` в `translation_ru`
- **matching** — сопоставление пар
- **sentence** — «Собери предложение» тапом по словам, восстанавливает
  `example_sentence` карточки (только active/mastered)
- **listening** — термин озвучивается через TTS вместо показа текста;
  карточки языка без голоса на устройстве отфильтровываются сами

Грамматика (раздел Теория, подробности ниже):
- Дриллы по теме (multiple choice, дистракторы — реальные ошибки, не шум)
- Экзамен на уровень — сертификационный, отдельно от практики

Диалоги и чтение — см. отдельные разделы ниже.

## Склад → активно → mastered
Новые карточки не сваливаются в SRS все разом:
- `status = 'backlog'` — карточка существует в БД, но не участвует в SRS
- Дозирование по дням: `intro_settings.new_cards_per_day` (по умолчанию 8
  на язык), `daily_intro_log` не даёт превысить квоту за день даже при
  нескольких сессиях. Внутри языка склад выбирается по темам — тема
  выбирается целиком, прежде чем начинается следующая
  (`server/backlog/introduce.js`)
- Ручной «буст» темпа — `POST /api/backlog/boost`, поверх обычной квоты
- `status = 'active'` + `activated_at` — карточка вошла в SRS
- `mastered_at` — «уже знаю», карточка больше не показывается ни в SRS, ни
  в квизах (`POST /api/cards/:id/master` / `/unmaster`), учитывается как
  выученная во всей статистике наравне с обычным SRS-прогрессом

Почему так: без дозирования большой залповый импорт слов (а тут бывают
разовые добавки по 100-250+ слов) обрушил бы SRS-очередь на повторение.

## CEFR-уровни
У каждой карточки есть `level` (A1-C1), проставлен вручную по фактической
сложности слова, не штампом всей темы (`server/backfill-levels.js` для
существующих на момент введения поля; новый контент получает level сразу
при добавлении). Используется в экзамене на уровень (см. ниже) — фильтрация
по уровню в остальном UI пока не подключена, это просто данные.

## Теория (грамматика)
Две параллельные системы, обе живут под разделом «Теория»:

**Мой план** (`theory_courses` → `theory_blocks` → `theory_items`,
`server/routes/theory.js`, `client/src/pages/Theory*.jsx`) — личный
20-часовой план с план/факт минутами и чек-листом по пунктам. Сид —
`server/seed-theory.js`, по умолчанию 2 курса (казахский, английский) из
профилей выше; распределение уже пройденных тем по блокам — черновое,
пользователь может переразложить через UI.

**Справочник** (`theory_topics` → `theory_sections`,
`server/routes/theoryReference.js`, вкладка «Справочник») — независимый
мини-справочник тем с explanation/example/common_mistake секциями и
собственным прогрессом чтения. 44 темы (12 исходных kz A2 + 12 исходных en
B2 + по 12 новых на каждый язык, добавленных 2026-08-21). Сгруппирован по
`category` (например «Падежи», «Глагол: время и наклонение» для казахского;
Tenses, Articles, Prepositions для английского) — уровень категории **не
хранится**, считается на лету из уровней её тем, чтобы не могло разъехаться
с данными.

- Опциональная связка тема карточек ↔ slug темы справочника
  (`theory_theme_links`) — на карточке ссылка «Теория», на теме справочника
  блок «Практика» + «Учить эти слова»
- Дриллы (`theory_drills`, кнопка «Начать дриллы» на странице темы) — у всех
  44 тем есть упражнения, 220 дриллов всего, ~5 на тему. Дистракторы —
  реальные грамматические ошибки (не тот вариант гармонии/звонкости
  суффикса и т.п.), не случайный шум. Трекается `session_type =
  theory_drill`, точность **не** подмешивается в общий график точности
  квизов
- **Экзамен на уровень** (вкладка «Экзамен», `server/routes/exam.js`) —
  сертификационная проверка, не практика: до 50 случайных вопросов из
  накопленного пула дриллов этого языка+уровня, нужно 100% правильных
  ответов, без частичного зачёта. Отдельного банка вопросов нет — пул это
  просто «все дриллы тем этого уровня», растёт сам по мере добавления
  новых тем. Результат считается на сервере (перепроверка каждого ответа
  против `theory_drills.correct_answer`, не доверяется клиенту), полная
  история попыток в `level_exam_attempts`. На 2026-08-21 пул ещё небольшой
  для некоторых уровней (kz A1=5 вопросов, en C1=10) — это ожидаемо, не
  баг, будет расти вместе с темами

## Раздел чтения
Вкладка «Чтение» в Теории (`server/routes/reading.js`,
`client/src/pages/ReadingDetail.jsx`). Тексты с `level`/`theme`/`style`:
- `style = 'textbook'` — плотно завязан на уже существующую в колоде
  лексику, минимум новых слов
- `style = 'genre'` — аутентичный жанровый регистр (сказка, маркетинговая
  статья и т.п.), допускает больше новых слов ради естественности языка

**Весь текст — оригинальное авторство, ничего не скопировано из внешних
источников** (см. «Стратегия обучения» выше про юридическую причину). После
текста — упражнения на понимание (multiple choice), оценка server-side,
лучший результат хранится в `reading_progress.best_score`. Новые слова,
которых нет в колоде, — отдельным блоком, как в диалогах. 4 текста на
2026-08-21 (по 2 на язык), растёт со временем как и остальной контент —
не финальная библиотека.

## Диалоги
Вкладка «Диалоги» в Теории (`server/routes/dialogues.js`) — сценарные
диалоги (базар/такси/кафе), каждая реплика с озвучкой и переводом.
Построены преимущественно из уже существующих в колоде слов —
немногочисленные новые слова показаны отдельным блоком «Новые слова», а не
молча подмешаны.

## Озвучка (TTS)
Кнопка 🔊 в Study/Browse/«Мои знания»/Диалогах/Чтении — браузерный Web
Speech API (`client/src/utils/tts.js`), без бэкенда и файлов. Кнопка сама
скрывается, если у устройства нет голоса для языка. **На iOS (и Safari, и
Chrome — общий движок WebKit) казахского голоса нет вообще ни у одного
браузера** — это подтверждённое платформенное ограничение Apple, не баг и
не гонка загрузки голосов (гонка была реальной на Android и починена
2026-08-21, но на iOS дело не в ней). Не пытайся снова "чинить" отсутствие
кнопки на iOS без пре-generated аудио/серверного TTS — это отдельная,
осознанно не начатая задача.

## Геймификация
XP и уровни (`server/xp/`, уровень = растущий порог `round(100 * N^1.5)`),
бейджи, личные рекорды, streak (дней подряд с завершённой сессией любого
типа). Leech-детект — карточка «зависла», если `easiness_factor ≤ 2.0`
(старый SM-2-сигнал, застыл) ИЛИ `fsrs_difficulty ≥ 7` (актуальный
FSRS-сигнал) после хотя бы одного повторения
(`LEECH_CONDITION_SQL`/`LEECH_ORDER_SQL` в `server/routes/gamification.js`,
переиспользуется и в проблемных карточках на дашборде, и в координационной
сводке). «🎯 Тренировка дня» — одна кнопка на дашборде, собирает сессию из
лечей + due-карточек. Квесты (дневные/недельные) считаются на лету из тех
же таблиц, отдельного трекинга прогресса нет.

## Координационная сводка
`GET /api/coaching/summary` — по каждому языку: прогресс по CEFR-уровням,
самые слабые темы, топ проблемных карточек; плюс streak, минуты за неделю,
сравнение точности чтения/письма vs аудирования. **Это НЕ автоматическая
AI-интеграция** — пользователь вручную запрашивает этот эндпоинт и вставляет
результат в разговор с Claude (в отдельной сессии, не в этой), чтобы
получить совет. Если попросят "доделать AI-координацию" без явного запроса
на реальный вызов внешнего API — не начинай это самостоятельно, это
осознанно отложенное решение (обсуждалось 2026-08-21).

## Telegram-бот
Есть (`server/telegram/bot.js`) — напоминания, `/stats`, `/due`, недельный
recap, уведомления об уровне/бейджах. Активируется токеном в
`server/.env` (`TELEGRAM_BOT_TOKEN`). **На 2026-08-21 токен не задан** —
бот не активен на живом сервере. Не предполагай, что он работает, если не
проверил `.env` заново.

## Что важно трекать
- сколько карточек выучено / осталось на сегодня, по языкам
- streak — дней подряд с хотя бы одной завершённой сессией (любой тип:
  study/quiz/theory_drill/level_exam/reading)
- суммарное время, потраченное на упражнения — по дням/неделям, **и
  отдельно по языку** (`study_sessions.language`, `GET /api/stats` →
  `minutes_by_language`). Сессии без выбранного языка (вкладка «Все» может
  смешать kz+en карточки) не попадают ни в один языковой счётчик
